# 阶段 0 · 询价工作台与报价工具提案

2026-11-21，供项目负责人评审。范围依据为 Pachat #196《项目总任务书 V1.0》及 #198。本文是 sukiyaki-Codex 负责的产品与工具部分，可供协调人汇入 PRD、架构、任务表与风险清单。全组阶段验收由项目负责人决定。

## 12 月底让谁完成什么任务

建议首位使用者为货代公司的报价操作员。操作员收到一封模拟邮件，在同一工作台完成缺项追问、合成 SOP 与运价查证、基础运费试算和内部报价草稿审核。审核员能判断用了哪条规则、哪些费用未知、自己批准的是哪一版。演示结束后，组员能在另一台电脑打开同一版本并复现结论。

首批样例限定中国至巴西海运单一商品。客户输入是自由文本，金额由程序从选定运价版本计算。邮件发送、订舱、支付、真实账号和生产运价另行立项。建议把企业知识检索纳入首版的一小段：至少提供一条可引用的合成 SOP，和一个资料中找不到答案的问题。

建议沿用模块化单体：浏览器收原文→本地千问输出字段或追问→只读知识/运价查询返回引用→操作员确认本次分类与试算→Python 计算内部草稿→审核员批准或驳回该草稿→SQLite 保存版本与结果。区分试算许可和草稿业务审核，两次决定分别记录用途。候选、查询失败或超时都应保留原文和停止原因。

工作台、工具和后端先对齐下列数据：case_id、draft_version、原文、商品、目的地、运输方式、总重及单位、总体积及单位、箱数、所选服务、source_id/version/SHA/页签/单元格、计算规则版本、分币种小计、未决费用、approval_id、审批对象及状态。估价相关字段或来源变化应生成新版本。模型只持有查询和试算申请能力；前端以服务端决定记录显示结果。单机合成阶段复用 SQLite 和 LM Studio；共享数据库、复杂调度和外部运价 API 会增加账号、部署和恢复工作，待多人业务试点另行评估。

### 联调样例口径（供复核）

| 样例 | 输入及依据 | 负责人应看到的结果 |
| --- | --- | --- |
| A · 基准 | 塑料收纳盒 30 箱，巴西海运，3 CBM、400 kg；合成 A 的 1–5 CBM 档为 820 USD/CBM | 基础运费 2,460 USD；最终应付待核。能从草稿打开 A 的引用 |
| B · 切换 | 保持相同货物与数量，切至合成 B；为便于人工独立验算，建议 B 的同档费率设为 760 USD/CBM | 预期 2,280 USD。界面列出 B 的引用；旧审批无法用于新版本，原草稿仍可追溯到 A |
| SOP-01 §1 · 资料不齐 | 合成规范文本：「巴西海运基础运费试算须有明确品名、运输方式、目的国、整票总体积与总毛重。缺少必要字段时，列出缺项并向操作员追问。」 | 输入“30箱收纳盒海运到巴西，总重400公斤”时追问总体积，能定位到 SOP-01 §1 |
| SOP-01 · 无依据 | 询问“巴西目的港免堆多少天？”；样例规范及运价表均不含此条款 | 明示现有资料无法确定，请操作员补充船公司或目的港条款；不生成天数 |

B 的单价及 SOP 措辞是我方提出的验收样例，均为合成数据。本轮交付为规划口径；实际文件、哈希和运行回执由实施阶段记录。请接口负责人核对切换来源后的版本与审核语义，请独立验收组员复核上述预期值及无依据场景，请协调人把有异议的条目和负责人决定写入统一方案。

阶段 0 通过前，本组交付以规划和已有证据为限。请协调人汇总团队分工、依赖、总体路线与风险清单；请负责人把最终范围、阶段结论及条件写入统一仓库。

### 2026-11-21 验收样本交接

已固化 [A/B 运价、SOP-01 v1、SHA256SUMS 和复核脚本](../data/sample/fp01/)。两份 Excel 仅首档 E5 提供测试费率；其余品类行为固定格式占位。仓库根目录执行 `python3 data/sample/fp01/verify.py`（Windows 可用 `py -3`）即可在临时库导入两份表，按文件 SHA 指定来源，实际调用分类及试算工具。3 CBM、400 kg 按 A→B→A 切换得到 2460.00、2280.00、2460.00 USD；三次均保留来源和 E5，最终应付为空。脚本中的规则记录仅供合成验收。SOP 已交付为资料；页面切换、旧审批失效事务与知识检索属于后续独立验收项。
