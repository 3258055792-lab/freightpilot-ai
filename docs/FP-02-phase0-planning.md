# FreightPilot AI 阶段 0 · FP-02 审批与验收建议

供团队汇总到 PRD、架构、任务分配和风险清单。阶段 0 的交付是规划与验收标准。本文的分工和优先级由团队讨论后提交项目负责人确认。

## 首版场景

首版服务货代报价操作员与审核员。用一份合成询价走通信息提取、缺项检查、分类、运价依据查询、生成内部草稿和人工审核。操作员能看见待补字段、依据和草稿版本，审核员能看到申请时锁定的资料并批准或驳回。客户邮件发送、订舱、付款、真实企业数据接入和多 Agent 调度列为后续候选。

## 建议架构

保留现有原型，先用本机 Python 和 SQLite 验证报价草稿的审批边界。模型只提取信息和请求工具，确定性工具从固定来源出具试算，服务端根据已认证身份决定操作权限。草稿锁定案例 ID、版本、影响试算的输入、来源版本和字节哈希。批准和执行的权威证据分别取自服务端的决定记录和持久结果，工作台按记录显示状态。

备选方案是直接用团队共享的数据库和身份系统。它适合多用户试点，也会把部署、身份集成、备份和故障恢复纳入首轮验收。首次需要跨机器多人使用或接入真实业务数据时，需在该环境重新验证身份、权限和数据隔离。首版合成演示可以先核对工作流与证据，减少基础设施变量。

最大的风险是重量、体积或运价来源变更后，旧批准仍能通过。批准应绑定到确切的草稿版本和快照。发生变更时生成新草稿，重新核对依据并申请批准。旧决定保留在审计记录中。主界面上的批准状态由后端返回。

## 后续联调验收清单

本表定义后续联调的预期行为。验收时以同一套合成数据及固定前后端版本记录输入、实际结果和持久记录引用。

| 场景 | 预期行为 | 核对依据 |
| --- | --- | --- |
| 缺重量、体积或目的地等关键字段 | 显示待补字段，补全后再试算 | 待补清单，审批和效果记录均为空 |
| 运价来源缺失或不适用 | 停在查证，保留原询价和原因 | 来源状态，草稿无金额 |
| 有依据的完整询价 | 生成内部草稿并等待审核 | 草稿版本、来源哈希、待审核记录 |
| 申请后把重量从 400 kg 改为 800 kg，或改选运价来源 | 旧批准无法用于新草稿，新草稿需重新审批 | 新旧案例版本和快照哈希，旧批准查询结果 |
| 模型或查看者尝试批准 | 服务端拒绝，草稿审批状态保持原值 | API 状态及持久决定记录 |
| 重试创建或模拟执行 | 同键同载荷返回原记录，载荷变化时拒绝，单一批准只消费一次 | 审批 ID、操作 ID、效果 ID、结果哈希 |
| 审核拒绝后重启，或模拟执行成功后重启 | 使用原 ID 查到同一决定或结果 | 重启前后查询记录 |

## 分工与交接

FP-02 建议承担草稿与来源绑定、角色权限、持久审批契约和以上验收用例，向团队提交相应章节。工作台与来源模块提供草稿字段及来源引用，独立验收成员按固定版本核对持久记录。先对齐这一份合成询价及字段，再确定各接口和验收负责人，最后将讨论结果合入团队的统一阶段 0 方案。跨系统业务写入需要执行回执和结果未知时的核对机制，应单独讨论后再排期。

阶段 0 收尾的检查项是确认首版范围、对齐同一个案例与接口字段、为各项交付指定一位负责人，并把联调预期写入统一规划。规划提交后由项目负责人确认开发顺序。

| 核查项 | 当前证据与交接 |
| --- | --- |
| 草稿版本与事务 | 保存时检查 `expected_version`，在一次 SQLite 写事务中保存新版输入、推进案例版本、失效旧待审/已批准记录并写审计。申请核对当前案例版本和已保存输入，决定核对审批修订号和快照哈希。以不同会话交错保存与批准测试最终一致性：旧版本最终不可被消费，新版本须重新申请。 |
| 审核人身份 | 独立 Python HTTP API 从服务端配置识别测试角色。工作台 `/drafts` 是另一条路径，其适配器固定使用本机模拟人类与模型身份。接入真实或多人审核前，用服务端认证会话确定审核人，校验案例权限并持久化决策主体。独立验收应确认操作员、模型和查看者不能作审核决定，合法审核人可以完成。 |
| 试算与审核对象 | 千问询价弹窗的试算许可关联进程内任务。案例页审批范围是 `classification_trial`，且两条路径各自运行。首版接口提议让试算许可关联操作 ID 和固定输入，草稿审核另持 `approval_id` 绑定已经持久化的 `case_id`、`draft_version` 和草稿快照哈希。前者只准许指定试算，后者记录人对该版本草稿的决定。验收时检查单有试算许可无法得到「草稿已审核」，两种事件都能追到同一案例的对应记录。 |
| 运价 A/B 与来源绑定 | 当前页面只提交品名、重量和体积，工作台适配器固定选审批种子来源。两项数量和品名都相同时，仅改目的地或运输方式也不会触发后端的新版本。正式草稿审核需要把所有影响试算的输入、运价版本、原始字节 SHA-256、命中规则引用和试算回执绑定到同一份快照。改表时，在同一写事务中固定新来源、生成新版并失效旧待审/批准，保留 A 版决定和证据。3 CBM × 820 USD/CBM = 2,460 USD，3 CBM × 760 USD/CBM = 2,280 USD，均为基础运费。B 的 2,280 USD 是规划期预期值，需用交付的 B 原始文件、哈希和实际结果验证。 |

保留既有分工：FP-02 负责草稿审核契约、服务端角色和来源变更事务方案。FP-01 提供 A/B 的固定样例、选择入口、运价规则和工作台接入，FP-03 按固定联调版本独立复测。当前可交给验收方的直接接入点是 `POST /cases/{id}/draft`、`POST /approvals`、`POST /approvals/{id}/decisions`、`GET /approvals/{id}` 及同版服务的持久查询。工作台的 `/drafts` 适配器保留为合成演示入口，生产身份与草稿审核的具体接口仍待团队确认。
