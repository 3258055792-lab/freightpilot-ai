# 原型迁移记录

日期：2026-11-16。

原型从本机 FreightAgent-Test 复制到 prototype/，原目录未修改。迁移包括 Excel 提取、待审核数据导入、工作簿存档、分类/试算工具、Harness 适配器及已有回归测试。

## 可移植性调整

- 移除个人 npm 缓存绝对路径，使用 package.json/package-lock.json 安装 SDK。
- Python 子进程支持仓库虚拟环境的 Mac/Windows 路径及 FREIGHT_PYTHON 覆盖。
- 测试分离到 prototype/tests；源码模块暂时保留原型布局，减少业务逻辑改动。
- 旧测试硬编码的真实工作簿文件名与 SHA 改为合成工作簿和运行时哈希。
- 新增合成 Excel、JSON 和数据库生成器，数据不进入 Git；包含故意构造的重复商品、限定词、非数值运价等边界场景。
- 生成器中的规则确认记录仅模拟测试前提，不能表示正式人工授权。

## 不迁入的本机内容

真实企业运价 Excel、原数据库及其工作簿二进制存档、旧提取结果、模型/聊天记录、.dsh、虚拟环境、缓存、日志、凭据和本机启动器。旧 README 中依赖真实业务文件的描述被新的运行说明替代。

## 验证范围

本机 Mac 运行 Python 34 项及 Node 18 项回归测试。涵盖待审核约束、重复导入、回滚、数值/档位、分类证据、拒绝审批、取消、重复审批以及输入快照绑定。

GitHub Actions 配置 Mac/Windows 验证；只有发布分支后才会在远端运行，本次不能声称已经通过 Windows 验证。未执行真实模型、船公司接口或订单端到端测试。

## 当前限制

Harness 仍为预发布 SDK，适配器测试使用模拟审批服务，不能证明真实 UI 审批联调全部正常。Python API 可直接试算，但始终返回非正式报价；未来业务系统必须另建身份、权限、持久化审批与订单幂等边界。

## 依赖核验结果

迁移初始使用原 SDK 0.2.2-rc.1，npm audit 报告 8 项高危依赖告警（含 Zod 约束集合验证内存耗尽及依赖传播）。升级到 0.2.2-rc.3 并重新解析锁文件后，npm 报告 0 项已知漏洞；重新运行 34 项 Python 与 18 项 Node 测试均通过。此结果仅代表本次依赖数据库检查，不构成完整安全审计。
