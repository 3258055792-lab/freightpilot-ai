## 后台独立结论

- 角色/伪造字段被拒绝，未产生有效决定或效果；同键同体重放原审批，异载荷冲突。
- 两个不同操作争用一个批准，仅一个成功，持久操作/效果/结果各一条；服务真正重启后仍返回原结果。
- 拒绝后重启和新操作重试持续被阻断。
- 隔离数据库的案例版本和来源引用同时变更后，旧批准失效；不是第二来源 UI 切换测试。
- 本地测试身份不证明真实人类身份。未覆盖事务提交中崩溃、外部副作用恢复、同版本来源原字节被篡改，以及实际工作台联调。上游测试有四条 HTTPError 资源清理警告，断言均通过。

## 阶段 0 的独立意见

按 #196/#198/#199，只盘点、规划和验证既有原型，不推进新业务功能。建议奶龙汇总单一阶段 0 文档；FP-03 负责证据分级、阶段验收门槛、失败用例和可复现性。建议复用现有分类、来源引用、输入防护、合成审批；MVP 先走缺项追问→有依据草稿→人工审核，发送邮件、订舱及多 Agent 调度后置。

不同意见与取舍：阶段 0 的文档可用评审和证据核对验收，无需机械要求所有测试类型；运行功能的测试随适用阶段进入门槛。前端演示审批和服务端授权必须分开记账；“批准前允许草稿预计算”或“批准后才允许计算”应在统一产品契约中选定，不能由两端各自解释。第一版先完成一次可靠闭环，比增加 Agent 数量更容易验收。

开源复用核查：[Microsoft Playwright](https://github.com/microsoft/playwright) 可作为后续浏览器回归基础；本轮复用已有 Edge 扩展接口、Node/Python 标准测试工具，没有新增框架依赖。针对货代 Agent 的简短 GitHub 搜索尚不足以确认可直接采用的成熟业务系统，因此不作现成平台已选定的结论。
